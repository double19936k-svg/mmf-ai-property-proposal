# MMF 是什么（一页版 V0.1）

MMF 是装在本机电脑上的 **物业服务方案 / 投标技术方案辅助工具**。浏览器只是操作界面，程序默认只在本机 `127.0.0.1` 使用，不主动开放到外网。

它不是一个聊天窗口。当前版本把招标资料、需求梳理、可选 AI 引擎和 Word/PPT 输出串成一条工作流，让人从改初稿开始，而不是从空白页开始。

**定位：AI 辅助生成初稿 + 人工最终审核。**  
不是全自动投标，也不能替代专业判断。

## 能做什么

- 上传招标或需求文件（先在本机解析），或直接填写项目情况  
- 整理需求，形成统一方案结构，再按章节生成完整物业服务方案 Word  
- 可选生成 PPT（需安装 Node；只出 Word 可以不装）  
- 在页面配置千问；本机 Grok 为可选项；Kimi 也可填 Key 试用  
- 长文按章生成，中断后可从当前章节继续  
- 成品可打开目录、下载；历史记录可删  

当前对外试用请用本仓库源码包：双击 `首次安装.cmd` 后启动。版本 `0.1.0-alpha`，属于初始可部署 / Alpha，不是商用成品。

## 怎么用

1. 双击 `首次安装.cmd`，再双击 `启动MMF.cmd`  
2. 浏览器打开后设置输出目录，到「AI引擎设置」保存并测试连接  
3. 用「从需求文件创建」上传招标，或用「新建方案」填写 Brief  
4. 确认拟使用的经验后生成，到输出目录打开 Word/PPT  
5. 自己审稿后再决定能不能用  

未确认的人数、时限、收费不要填写，更不要直接写进投标文件。测试引擎只验证流程，不能当正式方案。

## 目前做到什么程度

已有样例（006D R10，内部基线样例项目）做到约 **70 页量级 Word** 和 **40 页 PPT**，作为版式与治理基线。006E 正式包已能按 **27 章计划分章生成**，并在本机跑通安装、检查点和篇幅门禁。同一结构下，千问 / Kimi / Grok 都能按章写正文，但篇幅和写法仍有差别。

这些是当前测试结果，不是每个项目都会自动达到同样质量和页数。用千问或 Kimi 完整跑通一本正式 70 页投标稿，目前还没有作为对外验收项做完。

## 当前限制

必须人工终审。三百页级技术标尚未充分验证。WPS 分页兼容性未作为已通过项。扫描件和复杂附件仍可能识别不全。选用千问或 Kimi 时，生成内容会发到对应云端，不能理解为完全离线写作。人员编制、SLA、费用必须人确认。现阶段不是 commercial ready。生成耗时随引擎、文档长短和网络变化，没有固定分钟数。

## 适合谁试

适合经常写物业服务方案、能判断专业对错、愿意拿真实（可脱敏）项目对照的人。  
不适合指望一次生成就盖章投标、或不想审稿的人。

建议先用一份非敏感的真实招标试一版，重点看：有没有漏招标要求、结构是否像完整服务方案、专业段落能不能改着用、改稿量比从零写是否下降。**省不省事，请你自己判断。**
