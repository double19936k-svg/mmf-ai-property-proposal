# MMF Desktop / Local 使用说明

版本：0.1.0-alpha  
状态：初始可部署（不是商用成品）

这是一个安装在本机的物业方案生成工具。浏览器只作为操作界面，程序只在本机 `127.0.0.1` 运行，不会主动开放到局域网或公网。

## 1. 如何安装

1. 确认已经安装 Python 3.10 或更高版本。
2. 如需生成 PPT，再安装 Node.js。只生成 Word 可以暂不安装 Node。
3. 双击 `首次安装.cmd`，等待提示“安装完成”。
4. 安装会在程序目录内创建隔离的 Python 环境，不会改你电脑里其他 Python 项目。

## 2. 如何启动

1. 双击 `启动MMF.cmd`。
2. 程序会自动检查环境、启动服务，并打开浏览器。
3. 使用本仓库源码包即可。不要把 `runs`、`output`、`logs`、`.env`、`providers.local.json` 提交到 Git 或打进对外安装包。

如果浏览器没有自动打开，请访问：

`http://127.0.0.1:3050/`

## 3. 如何配置AI

第一次打开页面时，先完成“首次配置”：

- 输出目录：点击“选择文件夹”在电脑中挑选，不要手打路径。工作文件和日志由程序自动管理
- 默认 AI 引擎
- 默认输出 Word 或 PPT
- 是否启用本机 Grok Bridge（可选）
- 是否启用 AI 图片服务（千问万相或 Grok Imagine）

然后打开“AI引擎设置”：

- **千问**：填写模型和 API Key，点击“保存配置”，再点“测试连接”。
- **Local Grok Bridge（可选）**：状态分为已安装、需要登录、已连接。只有测试连接通过后才能用于生成。没有 Grok 不影响使用千问。
- **Kimi**：目前只保留入口，尚未完成官方认证，不能当作可用引擎。
- **AI图片服务**：默认使用千问万相，可与文字千问共用同一把 Key；也可改用 Grok Imagine（需要 XAI_API_KEY）。在“AI引擎设置”里保存并测试连接。未配置时不影响文字方案生成。

API Key 保存在 Windows 凭证管理器中。页面不会显示完整明文，也不会写进程序文件或日志。配置一次后，下次启动通常不用重新输入。

## 4. 如何生成

1. 打开“新建方案”，选择已经连接成功的 AI 引擎。
2. 填写项目名称、业态、场景、输出媒介和需求。
3. 先生成知识推荐，确认后再生成正式初稿。
4. 也可以从招标/需求文件创建，先本地解析，再确认需求。

测试模式（Mock）只验证流程，不能当作正式方案。

## 5. 文件在哪里

生成完成后，页面会显示输出目录。可以直接打开文件夹或复制路径，并用页面上的下载按钮获取 Word / PPT。

默认输出目录在程序文件夹下的 `output`。工作文件和日志由程序自动管理，不需要单独设置。

在「历史记录」中可以：

- 删除历史记录：只从页面列表中去掉这条，已生成的文件仍保留
- 删除历史记录与文件：同时删除这条记录和对应的 Word / PPT 等成品，删除后无法恢复

## 6. 常见错误

| 页面提示 | 常见原因 | 建议 |
|---|---|---|
| Provider尚未配置 | 还没填写千问密钥，或未测试连接 | 到“AI引擎设置”保存并测试 |
| 网络连接失败 | 无法访问AI服务 | 检查网络后重试 |
| 输出目录不可写 | 选择的文件夹没有写入权限 | 换一个可写目录 |
| 当前Grok Bridge不可用 | 本机没有Grok或未登录 | 改用千问，Grok是可选项 |
| 生成失败，请查看运行日志 | 生成过程出错 | 查看 `logs` 或该次任务目录 |
| PPT相关提示 | 没有安装Node | 可先生成Word，或安装Node后重新运行首次安装 |

本版本是初始可部署版，不是 commercial_ready / production_ready。
